Для портфолио это вообще стандартный подход:

Projects → Case Study → Demo (опционально)

То есть пользователь нажимает View project, попадает на страницу проекта и уже там видит:

Hero-секцию с названием
Краткое описание проблемы
Стек технологий
Несколько скриншотов
Что было реализовано
Интересные технические решения
Чему научился
Ссылку на GitHub (если можно показывать)
Ссылку на Live Demo (если есть смысл)

Для твоих проектов это особенно хорошо работает, потому что самое интересное там не в UI, а в инженерной части:

Job Tracker

Можно написать:

Built with Nuxt 4, Prisma and PostgreSQL. Includes advanced filtering, application lifecycle management, secure data access and responsive UI.

И отдельно рассказать:

SQLite → PostgreSQL migration
Prisma
Supabase
RLS
OAuth
PWA
Health Monitor

Там вообще есть чем похвастаться:

SVG charts without charting libraries
Responsive dashboard
PWA
Health metrics tracking
Filtering and reporting
The Hood

Тут можно красиво написать:

Community and recruitment platform connecting maritime professionals, recruiters and companies across the global shipping industry.

Звучит уже как настоящий продукт, а не просто "чатик для моряков" 😄

И ещё один плюс такого подхода: статьи из раздела Notes потом можно будет линковать прямо из Case Study.

Например:

Related notes:

What is RAG?
MCP in simple words
AI agents vs workflows

Получится цельная история: человек смотрит проекты → читает технические заметки → понимает, что автор не просто код пишет, а разбирается в архитектуре и современных технологиях.

Для поиска работы это работает заметно лучше, чем просто кнопка "Open App".
